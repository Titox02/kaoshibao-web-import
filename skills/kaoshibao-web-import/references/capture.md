# 考试宝网页逐题采集

## 准备（只需一次）

用户登录自己已获授权的题库，切到“背题模式”，展开答案和原解析，回到第 1 题。用当前获准的浏览器工具读取必要 DOM，找出实际 CSS 选择器。不要从前端私有对象、源码中的接口函数或 cookie 中取题。

Chrome 本地扩展由用户在扩展管理页开启开发者模式并“加载已解压的扩展程序”，选本技能的 `extension/` 文件夹。若由代理操作安装，按当前环境的安全规则取得具体确认；不能绕过浏览器工具限制。扩展仅有 activeTab、scripting、本地存储和下载权限，没有持久站点 host_permissions，没有外部代码与主动网络采集。采集不会把数据发给模型或其他网站。

先确认扩展作用域与授权目的；用户点击扩展按钮授予当前标签访问权。进入其他域名、增加权限或发布扩展不是本技能的默认工作。

## 配置字段

在扩展面板填写 JSON，字段均为 CSS 选择器：

- `bankTitle`：当前题库标题，唯一可见；换库即停止。
- `root`：仅包住当前题干、选项、答案、原解析的容器，不能是 body/html。
- `counter`：当前题号和总数，如 `1/1340、` 或 `第 1 题，共 1340 题`。
- `question`：root 内的题干正文，不含答案和解析。
- `options`：root 内各选项行；`optionKey`：每行原字母。`.before-icon` 是历史页面出现过的类，仅作核对线索，不保证新版仍适用。
- `answer`：含“正确答案”标签的最小容器，不使用“你的答案”、选项颜色或自选结果推测答案。
- `analysis`：含“解析”标签和原解析正文的最小容器。题干、答案、解析容器不能相互包含。
- `answerContent` / `analysisContent`：可选，分别在答案区/解析区内选择真正正文。外层仍需正确答案/解析标签，正文不带纠错按钮等界面文字。存在独立正文元素时应配置，避免把界面文字当成原解析。
- `type`：显示单选题/多选题等的元素；无可靠题型时留空，导入后人工核对，不猜题型。
- `next`：实际“下一题”按钮，唯一可见。
- `loading`：站点实际的加载标识；`ready`：确认本题加载完成的元素，可选但有可靠标识时应配置。
- `idAttribute`：root 上真正的题目 ID 属性（例如实际观察到的 data-question-id）。没有时留空，使用题号作为本次存档内 ID，不冒充平台 ID。

所有选择器先在当前 DOM 核对，不能复制占位文字或遍历猜测接口。对陌生页面只看一题，不扫整份题库。

## 试采、继续和停止

点“预览本题”：只显示题号、题干短预览、选项字母、答案短预览与解析长度。新建存档必须位于第 1 题；旧存档不会删除。先采 3 题并人工核对三题的题干、选项、答案与解析是否对应；导出后用 finalize_capture.py --allow-partial 做一次连续性及 ID 校验，再开始下一批；默认每批最多 25 题，上限 100。不要为省 token 盲目把批量放大。

每次读取同一题号前后核对，并要求题干、选项、答案、解析连续 4 次相同；每次间隔 800ms。保存后在点击下一题前再次确认页面指纹，下一题必须正好递增一题。每题分别落盘，避免整库来回重写。

这些检查降低异步错位风险，但稳定几秒不等于证明服务端已完成渲染。若页面无可靠加载/题目关联标识，必须通过实际抽查验证；无法确认时停止或改为逐题人工确认，不凭固定延时宣称可靠。重复题、同答案、相同解析可能合法，不能仅因正文相同去重。

当正确答案或原解析尚为空时停止。原网页明确显示“暂无解析”等，会作为原解析缺失记录；若只有空解析容器，需用户确认本题确实无原解析，使用面板“确认本题无原解析，仅保存本题”，只放行当前题号。

采集时保持原标签打开，不手动跳题、不切换题库、不自动切屏。面板可关闭；再次点扩展按钮查看统计。每批暂停在最后保存题；继续前保持在该题或下一道未保存题。刷新网页后仍可续采；关闭标签后若需恢复，重新打开原题库，手动定位最后已保存的题号，再点击“验证并恢复此标签”。只有题库标题、题号和完整内容指纹与原断点完全一致才会绑定新标签；不一致就停止，不用新建假装续上。

遇到验证码、账号异常、频率限制或题目不一致：停止、导出已有存档；不自动重试、换号、读取凭证或绕过限制。

## 导出、图片与校验

点“导出存档”保存 JSON。字段包含 name、expectedCount、exportedCount、complete、questions；每题包含题号、完整题干 HTML、原选项、正确答案、原解析 HTML、缺失标记和本地内容指纹。complete 仅表示题数齐全，不代表原题答案已学术校订或图片已离线保存。

扩展不会下载图片，不会调用原站接口。它保留当前题干/选项/答案/解析中的已显示图片地址和 MathML。图片需用浏览器允许的页面资产导出或人工另存；不要获取隐藏资源或带登录凭证的链接。无法保存时报告图片缺失，不标为完整离线。

图片映射示例（相对映射文件）：

```json
{"https://example.org/question.png":"images/question.png"}
```

脚本会复制 PNG/JPEG/GIF/WebP，按内容哈希去重。使用 finalize_capture.py --media-map 映射.json；缺图数量写入报告。原始 capture.json 单独保留作来源。

用户要求保留未完成成果时可用 --allow-partial，只生成明确标记不完整的预览；不能标为完整题库或直接上线。导入需要 Python 3.9+，无需 pip/npm。Windows 可用 py -3 替代 python3。

## 低 token 边界

模型只做首次选择器配置、异常排查和汇总。正常采集由本地扩展循环，正常转换由脚本完成，不调用模型 API。安装与 DOM 改版排查仍有上下文开销；人工逐题经浏览器工具读取通常更费 token。若当前环境不允许本地扩展采集，只能沿用获准浏览器工具，不能用另一条控制通道规避；说明开销后照授权范围执行。
