# 把已验证存档接入现有练习网站

## 明确实际结果

finalize_capture.py 生成独立离线网站和 questions.json，不会往线上发请求。接入现有网站是后续代码/数据适配流程；保留此边界，不宣称“已导入线上”。用户要求两个目标时，同一份校验数据复用，不重采、不重读整库进模型。

先定位用户指定站点的本地项目/仓库及现有导入机制。没有项目或权限时，准备完整本地包并询问缺失的目标，不搜索凭证。题库、个人进度、账号数据不放进公开仓库。采集与转换已获授权不自动授权生产部署；复用会话中针对同一目标的明确部署授权，仍遵守工具要求。

## 通用适配顺序

1. 用脚本读取现有数据 schema、题库/题目稳定 ID 与导入约束，仅向模型输出结构及少量样本。对接已有题库导入功能，不把用户答题记录导入端点当作题库端点。
2. 在新目录生成候选数据与差异报告；原题干、选项原字母、正确答案、完整原解析保持来源字段。AI 简析等单独保留，不能替换原解析。
3. 新题库用新 bankId/namespace；题目使用稳定源 ID。没有平台 ID 时使用本次题库内稳定题号，并明确来源；重新排序需迁移映射，不能按新序号覆盖旧答题结果。
4. 已有同库更新需明确 ID 映射与差异，保留旧版快照。遇到同 ID 不同内容、选项字母重排或语言变体，停下输出冲突清单，不自动去重合并。
5. 跟随项目现有导入/构建方式；验证题数、图片、公式、答案字母、人工核对题、原解析缺失数及用户进度隔离。网页联调使用独立测试账号/本机隔离进度，不修改真实用户记录。
6. 按已有目标授权进行发布；验证线上版本、题数、答题与解析、旧题和旧进度可恢复。没有部署授权则交付可审查的变更和明确未上线状态。

## 多题库与已有进度

接入已有项目时，先用项目文件确认真实数据约束，不套用其他站点的历史配置。

- 每个题库使用独立 bankId；原题稳定 ID 与答题记录分开管理。
- 进度同步接口只处理答题状态，不自动等于题库导入接口。
- 新增科目需同步检查前端入口、服务端题库校验与按库隔离的进度存储，不能只替换数据文件。
- 同库更新保留 ID 映射、旧数据快照和用户后来作答的记录；代码回退不要整库覆盖新进度。
- 多语言题目不能按相同序号自动配对；没有可靠对应关系的题目单独保留。

## 最终汇总

只报告来源已采数量/标示总数、缺失答案/原解析/图片、导入题数、目标 URL 或本地路径、实际已上线或待部署状态。不会因为校验完成而自动宣称原站内容没有错误。
